# Г3 — модуль обработки ошибок в заявках на перевозку вагонов

Первая рабочая версия к 20 ноября. Python 3.10+ (проверено на Python 3.13), стандартная библиотека, без установки зависимостей. Код работает локально; предполагаемое внедрение — серверный модуль импорта. Существующая система и БД не подключены, их границу заменяет экспорт проверенных заявок.

## Быстрый запуск (Windows / Linux)

Распакуйте исходный комплект «Данные_заявки.zip» в каталог `data/` проекта. Нужны:

- `applications_raw.csv` — 19 полей, исходные заявки;
- `labels_train.csv` — эталон только для train;
- `stations.csv`, `cargo.csv`, `clients.csv`, `wagon_types.csv` — справочники.

Из корня проекта:

```sh
python -m unittest discover -s tests
python -m rail_validator inspect data/applications_raw.csv
python -m rail_validator evaluate data --output output/eval
python -m rail_validator process data --split holdout --confidence output/eval/confidence.json --output output/demo
```

На Windows при отсутствии команды `python` используйте `py -3`. Откройте `output/demo/queue.html` в браузере. Сеть для этого не нужна. `ready.csv` — заявки без поставленных в очередь полей (не гарантия абсолютной корректности), `pending.csv` — частично обработанные, ожидают оператора. `audit.csv` — журнал автоматических и ручных рекомендаций.

Чтобы сравнить выгрузку baseline:

```sh
python -m rail_validator process data --method baseline --split holdout --output output/baseline
```

## Сценарий оператора

Очередь HTML содержит поиск, исходное значение, предлагаемый вариант, причину и оценку уверенности. Оператор редактирует `output/demo/operator_decisions.csv` (не меняя имена столбцов, app_id и field):

- `accept` — принять непустой кандидат;
- `edit` — вписать ручное значение в `operator_value`;
- `clear` — признать исходное значение допустимым;
- `drop` — отклонить заявку (например, подтверждённый дубликат).

Запуск после заполнения:

```sh
python -m rail_validator resolve output/demo --decisions output/demo/operator_decisions.csv --output output/resolved
```

`approved.csv` — готовые и полностью подтверждённые заявки, `pending.csv` — ожидающие, `rejected.csv` — отклонённые. Пустое решение оставляет заявку в очереди. Ручные правки доверены оператору, автоматической повторной валидации и интеграции с БД пока нет. ID заявки не перезаписывается. Не редактируйте исходные файлы данных.

## Архитектура и сравнение

1. CSV-адаптер сохраняет идентификаторы строками; даты понимает включая серийные числа Excel.
2. Локальные проверки форматов, контрольных цифр, справочников, совместимости, массы, договора, роли и дубликатов. `split` служебное поле; нет надежного способа подтвердить произвольный идентификатор заявки или корректность каждой бизнес-величины без дополнительных данных.
3. Baseline — простые проверки по формату и справочнику, автоматическое исправление только однозначного регистра/пробелов. Остальное — оператору.
4. Г3 — контекстная система правил с нечётким сопоставлением, восстановлением раскладки, проверкой станций клиента, поиском переставленных маршрутов, кандидатов для груза, ИНН, договора, типа вагона и единиц массы. Подбирает кандидатов по текущей заявке и доверенным справочникам. Отдельной обучаемой классификационной модели нет; из размеченной fit-части статистически оценивается надежность правил.
5. Автокоррекция Г3 только если нижняя граница 95%-го интервала Уилсона для точности правила на fit не ниже 0.95. Это групповая оценка правила, не индивидуальная вероятность правильности каждого исправления. Неоднозначные случаи передаются оператору.

## Воспроизводимая оценка

`evaluate` берет только официальный train (90 194 заявки), группирует одинаковое нормализованное содержимое без ID, времени и канала, затем случайно выделяет около 20% групп с seed=42 (18 039 заявок). Оставшиеся 72 155 используются для оценки надежности правил. Одинаковое содержимое не разносится между fit/holdout. Обработка идет в хронологическом порядке; для детектора дубликатов доступны только ранее поступившие raw-заявки из train, в том числе предыдущие holdout-заявки, но не их разметка. Официальный test не используется для калибровки и проверки метрик. Если исходник дубликата находится в test, он недоступен при этой оценке.

`metrics.json` — общий результат; `per_type.csv` — четыре категории по каждой строке разметки (несколько ошибок в одном поле могут иметь один кандидат); `examples.csv` — примеры пропусков и неправильных исправлений; `calibration.json` — надежность правил на fit. Precision/recall считаются по уникальным парам ID/поле; точность автоисправления — тоже по уникальным полям, включая неверные изменения исходно корректных полей. Доля остаточных ошибок включает пропущенные, неверно исправленные, переданные на ручную проверку и новые ошибки до решений оператора. Доля чистых без ручной проверки исключает все очередные заявки и неправильные автоисправления.

| Метрика | Baseline | Г3 |
|---|---:|---:|
| Размеченные ошибки исправлены правильно | 360 | 3476 |
| Исправлены неправильно | 0 | 20 |
| Переданы оператору | 3173 | 489 |
| Пропущены | 541 | 89 |
| Precision обнаружения | 82.74% | 99.12% |
| Recall обнаружения | 86.61% | 97.80% |
| Точность автоисправлений по полям | 100% | 99.14% |
| Заявок в очереди | 2459 | 484 |
| Остаточная доля заявок с ошибками | 14.34% | 3.03% |
| Чистые без ручной проверки | 85.66% | 96.85% |

Синтетический датасет, результаты не гарантируются на реальных данных.  Дальнейшую настройку после анализа holdout необходимо оценивать на новой неиспользованной выборке или закрытом test. Заявки с необратимыми/сомнительными ошибками в датах и перегрузом требуют решения оператора. Сложные сочетания, дубликаты, неформальные названия и взаимозависимые изменения требуют дополнительной проверки. В текущей версии нет отдельной модели истории клиентов, повторной проверки целостности после исправлений, прямого импорта email/XLSX, БД и веб-сервиса. CSV — согласованный формат учебного прототипа.

Обработка тестовой выборки:

```sh
python -m rail_validator process data --split test --confidence output/eval/confidence.json --output output/test
```

Исходные файлы размещаются в `data/`, результаты выполнения — в `output/`. Эти каталоги исключены из Git через `.gitignore`.
